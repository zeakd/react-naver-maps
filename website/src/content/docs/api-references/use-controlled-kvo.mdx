`useControlledKVO()`는 React prop 값을 네이버맵 KVO 프로퍼티에 단방향으로 동기화하는 훅입니다. 내장 오버레이 컴포넌트들이 내부적으로 사용하며, 커스텀 오버레이를 만들 때도 활용할 수 있습니다.

## 시그니처

```tsx
function useControlledKVO(
  target: naver.maps.KVO,
  property: string,
  value?: unknown,
): void;
```

| 파라미터   | 타입                   | 설명                                           |
| ---------- | ---------------------- | ---------------------------------------------- |
| `target`   | `naver.maps.KVO`       | 동기화할 KVO 객체                              |
| `property` | `string`               | 동기화할 프로퍼티 이름                         |
| `value`    | `unknown \| undefined` | `undefined`이면 동기화하지 않음 (uncontrolled) |

## 동작 방식

1. 마운트 때는 setter 를 부르지 않고 SDK 가 가진 값을 기록한다 (생성자에서 이미 적용)
2. 이후 렌더마다 `value` 가 마지막으로 맞춘 값과 다른지, SDK 값이 그 직후와 달라졌는지 본다
3. 둘 중 하나라도 그렇고 SDK 값이 `value` 와 다르면 setter 를 부른다 (`setPosition`, `setOptions` 등)
4. `value`가 `undefined`이면 동기화하지 않음 — uncontrolled 모드

그래서 사용자가 지도에서 바꾼 값(끌어 놓은 Marker 위치 등)은 다음 렌더에서 `value` 로 되돌아갑니다. SDK 가 값을 바꿔 저장하는 경우(`path` 를 KVOArray 로, `minZoom` 3 을 6 으로)에도 렌더마다 setter 를 부르지 않습니다.

비교는 값으로 합니다. `equals` 가 있는 SDK 값(LatLng, Point, Bounds 등)은 `equals` 를, 배열은 원소마다, 객체는 키마다 비교합니다. DOM 노드와 함수는 참조로만 비교합니다. 렌더마다 새로 만든 같은 값은 바뀌지 않은 것으로 봅니다.

## 사용 예

```tsx
import { useControlledKVO } from 'react-naver-maps';

function useCustomOverlay(
  instance: naver.maps.KVO,
  props: {
    position?: naver.maps.LatLng;
    visible?: boolean;
  },
) {
  useControlledKVO(instance, 'position', props.position);
  useControlledKVO(instance, 'visible', props.visible);
}
```

## 설계 참고

- `useLayoutEffect`로 실행 — paint 전에 KVO를 업데이트하여 깜빡임 방지
- KVO를 구독하지 않음 — 렌더 시점에 직접 비교하여 불필요한 리렌더 방지
- NaverMap의 `center`/`zoom`/`bounds`에는 사용하지 않음 — 상호 의존적이어서 전용 dirty diff로 처리
