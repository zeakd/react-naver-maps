## 리터럴로 넘기기

좌표·크기·영역 prop 은 SDK 객체와 리터럴을 모두 받습니다. 렌더마다 `new navermaps.LatLng(...)` 를 만들 필요가 없습니다. 값이 같으면 다시 넣지 않습니다.

| 값             | 리터럴                                                            |
| -------------- | ----------------------------------------------------------------- |
| `LatLng`       | `{ lat: 37.5, lng: 127 }` 또는 `[127, 37.5]`(**경도, 위도** 순서) |
| `Point`        | `{ x: 10, y: 20 }` 또는 `[10, 20]`                                |
| `Size`         | `{ width: 20, height: 30 }`                                       |
| `LatLngBounds` | `{ south, west, north, east }`                                    |

배열은 `[x, y]` 라서 위도·경도에서는 경도가 먼저입니다. 헷갈리면 객체 리터럴을 씁니다.

## SDK 값과 상수

`useNavermaps()` 가 돌려주는 것은 SDK 의 `naver.maps` 그대로입니다. 상수와 값 클래스는 거기서 씁니다.

```tsx
const navermaps = useNavermaps();
<CustomControl position={navermaps.Position.TOP_RIGHT}>…</CustomControl>;
```

## 좌표계

`naver.maps.TransCoord`, `TM128`, `UTMKCoord` 등 좌표 변환은 geocoder 서브모듈을 불러야 생깁니다(`submodules={['geocoder']}`). 불러오지 않으면 `navermaps.TM128` 이 `undefined` 입니다.

SDK 3.10.5 의 `naver.maps.Service.CoordinatesType.UTMK` 는 `undefined` 입니다(SDK 의 키 이름이 `UTMNK`). UTMK 좌표계는 문자열 `'nhn:2048'` 로 씁니다. 공식 문서의 `UTMK_NAVERCoord` 는 SDK 가 `naver.maps` 에 내보내지 않습니다.
