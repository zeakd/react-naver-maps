`react-naver-maps`는 네이버맵의 기본 기능을 유지하면서, React에서 다루기 쉬운 인터페이스를 제공합니다. 핵심 개념 세 가지를 이해하면 대부분의 기능을 활용할 수 있습니다.

## React 컴포넌트 인터페이스

네이버맵의 요소들을 React 컴포넌트 형태로 mount/unmount할 수 있습니다. children을 통해 렌더 여부를 결정할 수 있습니다.

```tsx
import { NaverMap, Marker } from 'react-naver-maps';

function MyMap() {
  const [showMarker, setShowMarker] = useState(true);

  return (
    <NaverMap>
      {showMarker && (
        <Marker defaultPosition={{ lat: 37.3595704, lng: 127.105399 }} />
      )}
    </NaverMap>
  );
}
```

네이버맵 네이티브 API에서는 `marker.setMap(map)` / `marker.setMap(null)`로 직접 관리해야 하지만, `react-naver-maps`에서는 React의 조건부 렌더링으로 처리됩니다.

## 이벤트 핸들링

네이티브 API에서는 리스너를 수동으로 추가하고 제거해야 합니다.

```js
// 네이티브: 리스너 추가
map.addListener('zoom_changed', zoomListener);
// 또는
window.naver.maps.Event.addListener(map, 'zoom_changed', zoomListener);

// 네이티브: 리스너 제거
map.removeListener(zoomListener);
// 또는
window.naver.maps.Event.removeListener(zoomListener);
```

`react-naver-maps`에서는 `on*` props로 간단하게 처리됩니다.

```tsx
// props로 전달
<NaverMap onZoomChanged={zoomListener} />

// props에서 제거하면 리스너도 자동 해제
<NaverMap />
```

모든 오버레이 컴포넌트가 `on*` 이벤트 핸들러를 지원합니다. 각 컴포넌트에서 사용 가능한 이벤트는 API Reference를 참고하세요.

### 도형의 clickable

네이버맵 SDK 의 도형(`Circle`, `Ellipse`, `Rectangle`, `Polygon`, `Polyline`)은 기본이 `clickable: false` 라서 포인터 이벤트를 버립니다. 이 라이브러리는 포인터 핸들러가 있으면 `clickable` 을 켭니다. 끄려면 `clickable={false}` 를 명시합니다.

```tsx
<Circle center={center} radius={300} fillOpacity={0.3} onClick={handleClick} />
```

- 켜진 도형을 누르면 지도의 `onClick` 은 호출되지 않습니다.
- 채우기가 없는 도형은 선을 눌러야 이벤트가 옵니다. 안쪽도 누르게 하려면 `fillColor`, `fillOpacity` 를 지정합니다.

```tsx
<Marker
  position={{ lat: 37.5, lng: 127.0 }}
  onClick={(e) => console.log('클릭!', e.coord)}
  onDragend={(e) => console.log('드래그 완료', e.coord)}
/>
```

핸들러가 변경되면 이전 리스너는 자동으로 해제되고 새 핸들러가 등록됩니다.

## Controlled / Uncontrolled

React의 [Controlled Component](https://react.dev/reference/react-dom/components/input#controlling-an-input-with-a-state-variable) 패턴을 지원합니다.

### Uncontrolled (기본값)

`default*` 접두사가 붙은 prop은 초기값만 설정합니다. 이후 사용자 조작에 의한 변경은 네이버맵이 자체 관리합니다.

```tsx
<NaverMap defaultCenter={{ lat: 37.5, lng: 127.0 }} defaultZoom={15} />
```

### Controlled (외부 관리)

`default` 접두사 없이 사용하면 React state로 값을 관리합니다. 사용자 조작과 프로그래밍 방식 모두 React state를 통해 제어됩니다.

```tsx
function MyMap() {
  const [center, setCenter] = useState({ lat: 37.3595704, lng: 127.105399 });

  return (
    <>
      <NaverMap
        center={center}
        onCenterChanged={(center) => setCenter(center)}
      />
      <button onClick={() => setCenter({ lat: 33.3590628, lng: 126.534361 })}>
        제주도로 이동하기
      </button>
    </>
  );
}
```

### 지원하는 컴포넌트

| 컴포넌트            | Controlled         | Uncontrolled                                    |
| ------------------- | ------------------ | ----------------------------------------------- |
| NaverMap            | `center`, `zoom`   | `defaultCenter`, `defaultZoom`, `defaultBounds` |
| Marker              | `position`         | `defaultPosition`                               |
| Circle              | `center`, `radius` | `defaultCenter`, `defaultRadius`                |
| Rectangle / Ellipse | `bounds`           | `defaultBounds`                                 |
| Polygon             | `paths`            | `defaultPaths`                                  |
| Polyline            | `path`             | `defaultPath`                                   |

NaverMap 의 controlled `bounds` 와 `centerPoint`, `defaultCenterPoint` 는 0.4 에서 deprecated 이고 다음 버전에서 없어집니다. 개발 모드에서 한 번 경고합니다. 처음 보여줄 영역은 `defaultBounds`, 바꿀 때는 `map.fitBounds()` 를 씁니다.

### 규칙

- **하나의 prop에 대해 controlled와 uncontrolled을 혼용하지 마세요.** `center`와 `defaultCenter`를 동시에 전달하면 `center`가 우선합니다.
- Controlled prop을 사용할 때는 대응하는 `on*Changed` 이벤트로 state를 업데이트해야 사용자 조작이 반영됩니다.
- 오버레이(Marker, 도형 등)는 사용자가 지도에서 바꾼 값을 다음 렌더에서 prop 으로 되돌립니다. 예를 들어 `draggable` Marker 를 끌어 놓아도 `onDragend` 로 state 를 바꾸지 않으면 다시 렌더할 때 `position` 으로 돌아갑니다.
- 지도의 카메라(`center`, `zoom`)는 prop 이 바뀔 때만 움직입니다. 사용자가 끌어 놓은 지도를 되돌리지 않습니다.
- 사용자가 지도를 끌거나 핀치하는 동안과 그 뒤 관성이 멈출 때까지는 바뀐 카메라 prop 을 넣지 않고, 멈춘 뒤(`idle`) 마지막 값으로 맞춥니다. 화면에서 1px 안의 차이는 같은 자리로 봅니다. `zoom` 도 함께 바뀌면 큰 쪽 zoom 에서 잽니다.
- `onCenterChanged` 값을 늦게 되돌려줘도(비동기 store, transition, setTimeout) 지도가 지나온 자리로 당겨지지 않습니다. 지도가 최근 2초 안에 알려 준 center 와 1px 안인 `center` prop 은 그 되울림으로 보고 따르지 않습니다. 일부러 그 자리로 보내려면 `map.panTo()` 를 씁니다. GL 의 실수 zoom 도 같습니다(정수 zoom 은 늘 따릅니다).
- 래스터 지도는 실수 zoom 을 반올림해 씁니다(15.4 → 15). 반올림해 같으면 zoom 은 그대로 두고 center 만 옮깁니다. GL 지도는 실수 zoom 을 그대로 씁니다.
- `center` 와 `zoom` 을 함께 바꾸면 `morph` 로 한 번에 옮깁니다. 따로 떨어진 변경은 애니메이션합니다. GL 에서 1초 안에 연달아 바뀌면(움직이는 대상을 따라가기) 애니메이션 없이 바로 옮깁니다.
- prop 은 값으로 비교합니다. `center={{ lat, lng }}` 처럼 렌더마다 새로 만든 같은 값은 바뀌지 않은 것으로 봅니다.

## 숨김과 수명

지도와 오버레이는 React 가 트리를 숨겼다 다시 보여도 같은 인스턴스를 씁니다. 지도 안의 컴포넌트가 suspend 하거나 `<Activity mode="hidden">` 으로 숨기면 지도는 영역만 숨기고, 오버레이는 지도에서 떨어집니다. 다시 보이면 같은 지도가 같은 center 와 zoom 으로 돌아오고 오버레이도 다시 붙습니다. `open` 인 `InfoWindow` 는 다시 열립니다. 인스턴스는 컴포넌트가 정말로 사라질 때만 정리합니다.

## 컴포넌트 계층 구조

```
NavermapsProvider        ← 인증 키 설정 (앱 루트)
  └── Container          ← 지도 DOM 영역 + Suspense
        └── NaverMap     ← 지도 인스턴스
              ├── Marker
              ├── Circle
              ├── InfoWindow
              └── ...    ← 오버레이 컴포넌트들
```

- `NavermapsProvider`: 인증 키를 Context로 제공. 앱 루트에 한 번만 배치
- `Container`: 지도가 렌더링될 DOM div. 내장 Suspense로 스크립트 로딩 처리
- `NaverMap`: 실제 지도 인스턴스. 하위에 오버레이 컴포넌트를 배치
