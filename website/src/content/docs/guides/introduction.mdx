React Naver Maps는 [네이버 지도 JavaScript API v3](https://navermaps.github.io/maps.js.ncp/)(이하 SDK)의 비공식 React 오픈소스 라이브러리입니다. 지도와 마커, 정보 창, 도형을 컴포넌트로 그리고, 바뀌는 값은 props와 state로 다룹니다.

<Example of={BasicMap} />

```bash
npm install react-naver-maps
```

React 19.0 이상이 필요합니다. 키 발급부터는 [빠른 시작](/react-naver-maps/guides/quickstart/)을, 0.3에서 올린다면 [0.3에서 0.4로](/react-naver-maps/guides/migration-from-03/)를 참고해 주세요.

## 설계

지도와 오버레이는 컴포넌트입니다. props가 바뀌면 SDK 객체에 반영하고, `on*` props로 리스너를 관리합니다. 컴포넌트가 사라지면 리스너와 객체를 정리합니다. 지도를 그리고 움직이는 일은 SDK가 합니다.

```tsx
<NaverMap defaultCenter={{ lat: 37.5666, lng: 126.9784 }} defaultZoom={15}>
  {places.map((p) => (
    <Marker key={p.id} position={p} onClick={() => setSelected(p.id)} />
  ))}
</NaverMap>
```

props 이름은 SDK 옵션 이름과 같습니다. 지도, 마커, 정보 창, 도형은 컴포넌트가 모르는 옵션도 SDK에 넘기므로 새 옵션이 생겨도 라이브러리 업데이트를 기다리지 않아도 됩니다. 컴포넌트가 다루지 않는 기능은 `ref`로 SDK 객체를 받아 직접 호출합니다.

`{ lat, lng }` 같은 객체를 렌더마다 새로 만들어도 값이 같으면 SDK에 다시 넣지 않습니다. `useMemo` 없이 사용해도 됩니다.

`<Activity mode="hidden">`이나 Suspense로 잠시 숨기면 지도와 오버레이를 화면에서만 분리합니다. 다시 표시하면 같은 SDK 인스턴스를 사용합니다.

자세한 규칙은 [핵심 개념](/react-naver-maps/guides/core-concepts/)에 있습니다.

## 사용하기 전에

SDK의 동작은 그대로 유지합니다. 예를 들어 `maxBounds`로 영역을 제한하면 가장자리에서 미끄러지지 않고 멈춥니다.

서버 렌더링에서는 `Container`의 영역만 그리고, 지도는 브라우저에서 SDK를 불러온 뒤 나타납니다([Next.js와 SSR](/react-naver-maps/guides/nextjs/)). 네이버 클라우드 콘솔에서 Maps Application을 만들고 지도를 띄울 주소를 등록해 주세요([인증과 키](/react-naver-maps/guides/auth/)).
