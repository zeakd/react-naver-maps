## 동작 방식

`react-naver-maps`는 React 19의 `use()`를 사용해 네이버 지도 스크립트를 불러옵니다. `useNavermaps()`를 호출하면 스크립트 로딩 Promise를 `use()`로 감싸 로딩이 끝날 때까지 컴포넌트의 렌더링을 중단합니다.

## Container의 내장 Suspense

`<Container>`는 내부에 `<Suspense>`를 포함하므로 별도로 감싸지 않아도 됩니다.

```tsx
// Container 안에서는 Suspense 불필요
<Container style={{ width: '100%', height: '400px' }}>
  <NaverMap /> {/* 내부에서 useNavermaps() 호출 */}
</Container>
```

`fallback` prop으로 로딩 UI를 지정합니다.

```tsx
<Container
  style={{ width: '100%', height: '400px' }}
  fallback={<div>지도를 불러오는 중...</div>}
>
  <NaverMap />
</Container>
```

## SSR / 정적 빌드와 함께 사용

`react-naver-maps`는 SSR 환경을 지원합니다. 서버에서는 네이버 지도 스크립트를 불러올 수 없어 `<Container>`의 외부 div(높이 포함)만 렌더링하고, 지도는 클라이언트에서 하이드레이션한 뒤 표시합니다.

이 구조에서는 `useNavermaps()`를 `<Container>` 안에서 호출해 주세요. Container의 내장 Suspense가 스크립트 로딩을 처리합니다.

```tsx
// ✅ 올바른 구조: useNavermaps()가 Container 안
function MyMap() {
  return (
    <Container style={{ width: '100%', height: '400px' }}>
      <MapContent />
    </Container>
  );
}

function MapContent() {
  const navermaps = useNavermaps();
  return (
    <NaverMap
      defaultCenter={{ lat: 37.5666, lng: 126.9784 }}
      defaultZoom={15}
    />
  );
}
```

```tsx
// ❌ 잘못된 구조: useNavermaps()가 Container 밖
function MyMap() {
  const navermaps = useNavermaps(); // Suspense boundary 없음!
  return (
    <Container style={{ width: '100%', height: '400px' }}>
      <NaverMap
        defaultCenter={{ lat: 37.5666, lng: 126.9784 }}
        defaultZoom={15}
      />
    </Container>
  );
}
```

Container 밖에서 `useNavermaps()`를 호출하면 SSR 시 suspend를 잡을 Suspense boundary가 없어 빌드가 실패합니다.

## Container 외부에서 useNavermaps() 사용

지도가 아닌 곳에서 `useNavermaps()`를 호출해야 한다면 직접 `<Suspense>`로 감싸야 합니다.

```tsx
import { Suspense, useState } from 'react';
import { NavermapsProvider, useNavermaps } from 'react-naver-maps';

function CoordDisplay() {
  const navermaps = useNavermaps();
  // SDK 객체가 필요하면 렌더마다 만들지 않고 한 번만 만든다.
  const [coord] = useState(() => new navermaps.LatLng(37.5666, 126.9784));
  return <p>{coord.toString()}</p>;
}

function App() {
  return (
    <NavermapsProvider ncpKeyId="YOUR_NCP_KEY_ID">
      <Suspense fallback={<p>로딩 중...</p>}>
        <CoordDisplay />
      </Suspense>
    </NavermapsProvider>
  );
}
```

## render function으로 간단하게

`<Container>`에 render function을 children으로 넘기면 별도 컴포넌트 없이 `navermaps` 네임스페이스에 접근합니다.

```tsx
<Container style={{ width: '100%', height: '400px' }}>
  {(navermaps) => (
    <NaverMap
      defaultCenter={{ lat: 37.5666, lng: 126.9784 }}
      defaultZoom={15}
    />
  )}
</Container>
```

## preloadNavermaps()

지도 페이지에 들어가기 전에 스크립트 로딩을 시작해 기다리는 시간을 줄입니다. `NavermapsProvider` 밖에서도 부를 수 있습니다.

```tsx
import { preloadNavermaps } from 'react-naver-maps';

// 라우터 수준에서 미리 로드
preloadNavermaps({ ncpKeyId: 'YOUR_NCP_KEY_ID' });
```

## 직접 쓰지 않는 SDK 로딩 훅

공식 문서의 `callback` 파라미터와 `naver.maps.onJSContentLoaded`는 Provider가 대신합니다. 서브모듈까지 다 불러오면 `useNavermaps()`가 풀립니다. 라이브러리가 `onJSContentLoaded`를 감싸 쓰므로 앱이 이 값을 직접 대입하지 않습니다. 대입하면 `useNavermaps()`가 풀리지 않을 수 있습니다.

페이지가 먼저 `maps.js`를 넣었으면 그 SDK를 이어받습니다. 한 페이지에서 SDK는 한 번만 불러오므로 처음 불러온 키·서브모듈·언어가 그대로 쓰입니다.
