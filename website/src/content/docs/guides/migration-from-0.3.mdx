0.4는 0.3과 같은 구조(`NavermapsProvider` → `Container` → `NaverMap`)와 같은 키(`ncpKeyId`)를 사용합니다. 대부분의 앱은 코드를 바꾸지 않고 올릴 수 있습니다. 해당하는 변경 사항을 확인해 주세요.

## TypeScript를 쓰면 `@types/navermaps`를 함께 올립니다

0.4의 타입은 `@types/navermaps` 3.10.0에 들어간 멤버(`naver.maps.BicycleLayer` 등)를 사용합니다. 그보다 낮으면 컴파일 오류가 날 수 있습니다. TypeScript를 쓰지 않으면 설치하지 않아도 됩니다.

```sh
npm i -D @types/navermaps@^3.10.0
```

타입을 직접 적은 코드는 아래 자리에서 컴파일 오류가 날 수 있습니다. 동작이 바뀐 것은 뒤의 절에 있습니다.

| 0.3                                                   | 0.4                                                     |
| ----------------------------------------------------- | ------------------------------------------------------- |
| `submodules: string[]`                                | `Submodule[]`. 변수에 담았으면 `Submodule[]`로 적습니다 |
| `onMapTypeIdChanged` 인자 `naver.maps.MapTypeId`      | 등록한 지도 유형의 ID도 와서 `string`이 포함됩니다      |
| `onKeydown`, `onKeyup` 인자 `naver.maps.PointerEvent` | `{ keyboardEvent }`. SDK가 실제로 주는 모양입니다       |
| `MarkerEvent`에 `mousemove`                           | 없습니다. SDK가 Marker에서 내지 않아 불린 적이 없습니다 |

## 바꿔야 하는 코드

0.4에서는 그대로 동작하고 개발 모드에서 한 번 경고합니다. 다음 버전에서 없어집니다.

| 0.3                                                  | 0.4                                                                                    |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `<NaverMap bounds={b} />` (controlled)               | 처음 영역은 `defaultBounds`, 바꿀 때는 `map.fitBounds(b)`, 읽을 때는 `onBoundsChanged` |
| `<NaverMap centerPoint={p} />`, `defaultCenterPoint` | `center`, `defaultCenter`                                                              |

`bounds`는 지도가 계산해 내는 값이라 맞춰도 prop과 같아지지 않습니다. `fitBounds`는 정수 zoom으로 맞추기 때문입니다.

## 달라지는 동작

### 숨겼다 보여도 같은 지도를 씁니다

지도 안의 컴포넌트가 suspend했다가 다시 표시되거나 `<Activity mode="hidden">`으로 숨겼다 보이면, 0.3은 지도를 새로 만들었고 오버레이는 이전 지도에 남았습니다. 0.4는 같은 지도와 오버레이를 그대로 사용합니다.

따라서 `onInit`은 다시 호출되지 않습니다. 다시 보일 때마다 `onInit`에서 실행하던 코드는 다른 신호로 옮겨 주세요.

### 드래그하는 동안에는 `center`, `zoom` prop을 넣지 않습니다

사용자가 지도를 끌거나 핀치하는 동안과 관성이 멈출 때까지는 바뀐 `center`, `zoom` props를 적용하지 않고, 멈춘 뒤 마지막 값으로 맞춥니다. 드래그 중에 props를 바꾸던 앱(위치를 따라가는 지도 등)은 사용자가 손을 뗀 뒤 반영됩니다. 화면에서 1px 안의 차이로는 지도를 움직이지 않습니다.

### 같은 값의 새 객체로는 지도를 건드리지 않습니다

prop을 값으로 비교합니다. `center={{ lat, lng }}`처럼 렌더마다 새로 만든 같은 값은 바뀌지 않은 것으로 봅니다.

- 0.3은 같은 값의 새 `center` 객체로 다시 렌더링하면, 사용자가 끌어 놓은 지도를 해당 위치로 되돌렸습니다. 0.4는 되돌리지 않습니다.
- 인라인 `path={[...]}`, `icon={{ ... }}`로 렌더마다 setter를 호출하지 않습니다.
- `GroundOverlay`는 같은 값의 새 `bounds`로 다시 만들지 않습니다.

오버레이(마커, 도형 등)의 되돌림은 0.3과 같습니다. `draggable` 마커를 끌어 놓아도 `onDragend`로 state를 바꾸지 않으면 다시 렌더링할 때 `position`으로 돌아갑니다.

### 방금 지도가 알려 준 위치로는 `center` prop으로 돌아가지 않습니다

`onCenterChanged` 값을 늦게 되돌려주는 앱에서 지도가 지나온 위치로 당겨지지 않도록, 지도가 최근 2초 안에 알려 준 center와 1px 안인 `center` prop은 따르지 않습니다. 그래서 "이전 위치로" 버튼처럼 방금 지나온 위치로 `center`를 바꾸면 움직이지 않습니다. 이럴 때는 `map.panTo()`로 옮겨 주세요. 자세한 규칙은 [핵심 개념](/react-naver-maps/guides/core-concepts/)의 Controlled / Uncontrolled에 있습니다.

### 핸들러가 있는 도형은 클릭을 받습니다

`Circle`, `Ellipse`, `Rectangle`, `Polygon`, `Polyline`에 `onClick` 같은 포인터 핸들러가 있으면 `clickable`을 켭니다. SDK 기본은 꺼져 있어 0.3에서는 핸들러가 불리지 않았습니다. 도형 위 클릭이 지도로 가야 하면 `clickable={false}`를 명시하세요.

### 고친 문제

- `useKVO`로 읽은 `center`, `zoom`이 지도를 따라갑니다.
- `key`로 지도를 다시 만들어도 빈 화면이 되지 않습니다.
- gl 서브모듈을 불러도 `onZoomChanged` 값이 `getZoom()`과 같습니다.
- 페이지가 `maps.js`를 먼저 불러도 지도가 뜹니다.

## 새로 쓸 수 있는 것

| 무엇                                       | 어디서                                              |
| ------------------------------------------ | --------------------------------------------------- |
| `BicycleLayer`, `CustomControl`, `GeoJson` | `react-naver-maps`                                  |
| `useAutoResize` (영역 크기 따라가기)       | `react-naver-maps/addons`                           |
| `geocode`, `reverseGeocode`                | `react-naver-maps/geocoder`                         |
| `HeatMap`, `DotMap`                        | `react-naver-maps/visualization`                    |
| `DrawingManager`                           | `react-naver-maps/drawing`                          |
| `Panorama`                                 | `react-naver-maps/panorama`                         |
| 라이브러리에 아직 없는 SDK 옵션을 prop으로 | [핵심 개념](/react-naver-maps/guides/core-concepts) |

서브모듈 경로는 `<NavermapsProvider submodules={['visualization']}>`처럼 해당 서브모듈을 불러야 씁니다. 빠뜨리면 불러오는 법을 담은 에러를 던집니다.
