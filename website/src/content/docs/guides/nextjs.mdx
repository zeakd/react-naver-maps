React Naver Maps는 서버 렌더링을 하는 프레임워크에서도 사용합니다. 서버에서는 지도 영역(`Container`)만 그리고, 브라우저에서 SDK를 불러온 뒤 지도를 띄웁니다. 저장소의 검사에서 Next.js(App Router), React Router, TanStack Start, Astro, Vite로 빌드, 서버 렌더링, 하이드레이션, 지도 조작을 확인합니다.

## Next.js App Router

라이브러리 진입점에 `'use client'`가 있어 서버 컴포넌트에서 import 해도 클라이언트 컴포넌트로 동작합니다. 다만 이벤트 핸들러나 state는 서버 컴포넌트에서 넘길 수 없으므로, 지도를 그리는 컴포넌트를 `'use client'` 파일로 따로 둡니다.

```tsx
// app/store-map.tsx
'use client';

import { useState } from 'react';
import {
  Container,
  NaverMap,
  Marker,
  NavermapsProvider,
} from 'react-naver-maps';

export function StoreMap({
  stores,
}: {
  stores: { id: string; lat: number; lng: number }[];
}) {
  const [selected, setSelected] = useState<string | null>(null);
  return (
    <NavermapsProvider ncpKeyId="YOUR_NCP_KEY_ID">
      <Container style={{ width: '100%', height: 480 }}>
        <NaverMap defaultCenter={stores[0]} defaultZoom={14}>
          {stores.map((s) => (
            <Marker key={s.id} position={s} onClick={() => setSelected(s.id)} />
          ))}
        </NaverMap>
      </Container>
    </NavermapsProvider>
  );
}
```

```tsx
// app/stores/page.tsx (서버 컴포넌트)
import { StoreMap } from '../store-map';

export default async function Page() {
  const stores = await getStores(); // 데이터는 서버에서 받는다
  return <StoreMap stores={stores} />;
}
```

- 키는 브라우저에서 쓰는 값이라 환경 변수로 둔다면 `NEXT_PUBLIC_` 이름(`process.env.NEXT_PUBLIC_NAVER_MAP_KEY`)으로 둡니다. 다른 사이트의 사용은 콘솔의 Web 서비스 URL로 제한합니다([인증과 키](/react-naver-maps/guides/auth/)).
- `dynamic(() => import(...), { ssr: false })`는 필요 없습니다. 서버에서는 `Container`가 높이를 가진 빈 영역으로 렌더되어 레이아웃이 흔들리지 않습니다.
- `NavermapsProvider`는 지도를 쓰는 페이지 가까이 두어도, 공통 레이아웃의 클라이언트 컴포넌트에 두어도 됩니다. SDK 스크립트는 한 번만 불러옵니다.

## useNavermaps를 쓸 때

`useNavermaps()`는 SDK를 불러올 때까지 렌더링을 중단합니다. `Container` 안에서 호출하면 내장 Suspense가 처리합니다. 밖에서 호출할 때는 직접 `<Suspense>`로 감싸 주세요. 자세한 내용은 [Suspense와 스크립트 로딩](/react-naver-maps/guides/suspensed-use-navermaps/)을 참고해 주세요.
